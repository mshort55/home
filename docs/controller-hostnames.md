# Automatic controller hostname preparation

The `controller_hostname` role restores missing certificate-hostname resolution from reviewed
inventory values before device authentication. It runs locally in the current container or native
controller. A working DNS answer or existing dedicated mapping needs no edit or sudo. An unresolved
name gets one dedicated `/etc/hosts` entry, using local sudo, followed by an actual resolver check.
Duplicate, shared-alias, conflicting hosts entries and conflicting DNS answers stop the operation.
The role preserves unrelated entries and supports container bind-mounted hosts files.

These local prerequisite writes run even during `--check`. Remote device operations retain their
existing check-mode behavior. Passwordless sudo permits unattended preparation; otherwise pass
`--ask-become-pass` to the invoking playbook and supply the controller's sudo password.

## FortiGate

Backup and DHCP-reservation roles automatically prepare `fortigate_controller_endpoint` before
opening their API session. This includes the delegated reservation checks inside Wi-Fi WireGuard
configuration and verification. The explicit `prepare-fortigate-controller.yml` command remains
available, but is no longer a required separate step after container recreation.

## iDRAC

Enroll its reviewed **current** endpoint in private inventory:

```yaml
idrac01:
  ansible_host: bmc.example.test
  idrac_controller_endpoint:
    hostname: bmc.example.test
    address: 10.77.40.10
```

The hostname must equal `ansible_host`. Snapshot, backup, boot and network workflows prepare this
endpoint before Redfish requests, including BMC-route verification. ISO workflows also use it when
`idrac_iso_manage_hosts` is true. ISO status explicitly disables hostname edits and continues requiring
working resolution; native image hosting still requires macOS.

`idrac_network.address` can describe a future network configuration, so it is never implicitly used
as the current endpoint for these workflows. During an address migration, update the explicit current
endpoint only after establishing the new address, and reconcile any old hosts entry deliberately.
Conflicting entries are not silently replaced. Inventories without `idrac_controller_endpoint` retain
their existing resolution behavior, including the older native ISO preparation path.

## Other controller prerequisites

SSH-facing roles already restore enrolled host trust from inventory using `ssh_trust`. Proxmox and
OPNsense API caches, guest seeds and their TLS/SSH identities persist under the repository; their
enrollment/preparation workflows remain responsible for recovery. They are not regenerated by this
hostname role. Fedora's guest DNS checks deliberately test the real network resolver and must not
be satisfied by inserting controller hosts entries.
